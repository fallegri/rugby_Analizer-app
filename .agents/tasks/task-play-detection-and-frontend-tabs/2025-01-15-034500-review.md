# Play detection engine with AI enrichment and tabbed frontend (v2)

This is the v2 pass after five issues from the v1 review were addressed: position contract mismatch (fixed — now emits `{x, y}` objects), O(n³) tackle detection (fixed — indexed dict for the main loop), unbounded module-level storage (fixed — moved to `app.state`), ruck/scrum overlap (fixed — cross-type deduplication added), and tab state loss (fixed — `activeTab` now in Zustand store).

Watch for: **Play type enum mismatch** — the backend emits `"line-out"` (with hyphen) but the frontend `PlayType.LINEOUT` expects `"lineout"` (no hyphen), causing line-out plays to silently fall through to the tackle fallback config in the UI (confirmed). **Residual O(n) linear scans in `_check_convergence`** — the main tackle loop now uses O(1) indexed lookups, but convergence verification still iterates the full route list twice per candidate tackle, making the overall complexity O(pairs × qualifying_timestamps × route_length) rather than the intended O(pairs × timestamps) (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The indexed-dict fix eliminates the dominant cubic term in tackle detection. However, `_check_convergence` was not updated to use the index — it still does two linear scans over the raw route lists to find an earlier point. For routes triggered only on qualifying (close + fast) timestamps this is a smaller population than before, but it's still O(R) per invocation where it could be O(1).

A new contract mismatch exists between the backend's `"line-out"` string literal and the frontend's `PlayType.LINEOUT = 'lineout'`. The `playTypeConfig` lookup falls through to the `|| playTypeConfig[PlayType.TACKLE]` fallback, so line-outs render with tackle styling and a "Tackle" label rather than crashing. The fix is trivial — either normalize the backend to emit `"lineout"` or add `"line-out"` to the frontend enum.

## Line-out play type string mismatch

The backend detector creates line-out plays with:

```python
play_type="line-out",
```

The frontend enum and config map:

```typescript
LINEOUT = 'lineout',  // no hyphen
```

```typescript
const config = playTypeConfig[play.play_type] || playTypeConfig[PlayType.TACKLE];
```

When a line-out arrives from the API with `play_type: "line-out"`, it doesn't match any key in `playTypeConfig`. The fallback assigns tackle styling — red color, shield icon, "Tackle" label. The user sees what looks like a tackle at the sideline. The tests don't catch this because `PlaysTimeline.test.tsx` never constructs a line-out scenario with the backend's actual string value.

## Convergence check retains linear complexity

The v1 fix built `player_time_indexes` and uses `index_a[t]` / `index_b[t]` for the main distance/speed checks. But `_check_convergence` receives the raw route lists:

```python
converging = self._check_convergence(
    route_a, route_b, t, self.TACKLE_TIME_WINDOW_S
)
```

Inside, it calls `self._get_point_at_time(route_a, current_time)` (linear scan), then iterates both route lists to find the closest earlier point:

```python
for pt in route_a:
    t = pt.get("timestamp", 0)
    if earlier_time - 0.5 <= t <= current_time - 0.01:
        ...
```

This runs only when a pair is already close and fast — a much smaller population than the full timestamp set. But for dense tracking data (30fps, 30-second clips), a route has ~900 entries, and each qualifying convergence check does 2×900 iterations. If 50 timestamp-pairs qualify per player-pair across 435 pairs, that's 50 × 435 × 1800 ≈ 39M comparisons in the convergence path alone. Passing the pre-built indexes and using a sorted-keys list with bisect for "closest earlier point" would reduce this to near-constant per invocation.

## Test coverage gap enabling the enum mismatch

No test exercises the full round-trip of a `"line-out"` play through to the frontend type system. The frontend tests use TypeScript enum values directly (`PlayType.RUCK`, `PlayType.TRY`) rather than raw strings as the backend would emit. An integration-level test or a shared schema would prevent this class of contract drift.
